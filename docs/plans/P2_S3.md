# P2-S3 — Domain & Evidence Contracts

## 0. Status

| Field | Value |
|---|---|
| **Phase** | P2-S3 |
| **Status** | Implementation Review Candidate（accepted review triage applied；runtime smoke / human review / closeout pending） |
| **Track** | EvidenceFlow Application Track |

本 Step 的目标是完成 EvidenceFlow v1 Domain Contract 与 LangGraph State Contract 的设计冻结和最小
运行时集成。

P2-S3 不改变 ODR 已冻结的 Supervisor–Researcher runtime topology，不引入新的 scheduler、retrieval
architecture 或 quality-control graph。

本 Step 以整体 Step 为开发管理单位。下文的 implementation slices 用于 Codex 内部组织和代码审查，
不要求每个 slice 都建立独立人工审批点。

只有出现以下情况时需要暂停实现并重新进行人工设计确认：

- 需要改变 Supervisor–Researcher graph topology；
- 需要改变现有 Agentic Supervisor 的运行时决策语义；
- 需要新增未在本计划中冻结的一等 Domain Model；
- 需要引入新的 persistence / retrieval infrastructure；
- 发现现有源码行为与本计划中的 Baseline assumption 明显冲突；
- 需要破坏 legacy contract 才能继续实现。

## 1. Goal

冻结并实现 EvidenceFlow v1 的 Domain Model、Graph State Schema 和 Parent / Researcher Contract，
为后续 Evidence-native Researcher、Claim Grounding 和 Evaluation 提供稳定的数据基础。

核心目标：

1. 将 generic `Research Brief` 升级为领域感知的 `MedicalResearchBrief`。
2. 将 free-form research topic 升级为结构化 `MedicalResearchTask`。
3. 定义 `Source → Evidence → Finding` 的 v1 Domain Contract。
4. 定义稳定的 `ResearchTaskResult`，作为 Researcher → Supervisor 的业务输出边界。
5. 明确 Parent Graph State 与 Researcher-local State 的职责和字段边界。
6. 明确 Process Artifact、Evidence Artifact 与 raw artifact 的边界。
7. 保留现有 ODR Supervisor–Researcher Tool Loop 与 legacy text path。
8. 为上述 Contract 建立 deterministic schema / invariant tests。

本 Step 完成后应能够解释并运行：

```text
User Question
  → Clarify
  → MedicalResearchBrief
  → Agentic Supervisor
  → MedicalResearchTask
  → Researcher boundary
```

以及能够解释未来链路：

```text
Researcher
  → SourceRecord
  → EvidenceRecord
  → ResearchFinding
  → ResearchTaskResult
```

P2-S3 不负责实现完整 Evidence extraction pipeline。

## 2. Baseline

本节描述冻结 commit 上的 **Baseline / Implemented** 行为，不代表 EvidenceFlow 原创实现。

当前冻结 Baseline 的主要业务控制流为：

```text
Clarify
  → Research Brief
  → Agentic Supervisor
  → ConductResearch Tool Calls
  → concurrent Researcher Subgraph runs
  → Compression
  → Supervisor observes and re-evaluates
  → Final Report
```

Agentic Supervisor 根据当前 Research Brief、已有 research results 和 State，在运行时动态生成 0/1/N 个
`ConductResearch` Tool Calls。

`supervisor_tools` 负责解析 Tool Calls、执行并发准入、构造 Researcher Subgraph input、调用独立
Researcher runtime instances、聚合结果并返回 Supervisor。

### 2.1 Research Brief

当前 Research Brief 主要是通用文本形式，用于将用户问题转化为较详细的 research specification。

其内部没有稳定表达医学 question type、clinical elements、constraints 和 evidence needs 的 typed
Domain Contract。

### 2.2 ConductResearch

当前 `ConductResearch` 主要通过 free-form `research_topic` 表达 Supervisor 的研究委派意图。

Research task lifecycle、domain intent 和 evidence requirement 没有成为显式的一等 Contract。

### 2.3 ResearcherState

当前 Researcher Subgraph 主要围绕以下运行信息工作：

- `research_topic`
- `researcher_messages`
- `tool_call_iterations`
- `compressed_research`
- `raw_notes`

Researcher 内部通过 Model–Tool–Observation Loop 完成检索和研究。

### 2.4 Researcher Output

当前 Researcher 主要通过以下字段向上层返回研究结果：

- `compressed_research`
- `raw_notes`

其中 `compressed_research` 是 Researcher context 的文本压缩结果；`raw_notes` 仍以 Tool / AI message
content 为中心。

Source、Evidence、Finding 等外部证据对象尚未形成稳定 typed contract。

### 2.5 Parent Observation

Supervisor 主要通过 ToolMessage / compressed research 等文本结果重新观察已有研究，并动态决定：

```text
ConductResearch(...)
```

或：

```text
ResearchComplete
```

P2-S3 保留这一 Agentic decision loop，不重写 Supervisor 的 planning algorithm。

## 3. Scope

以下内容属于 **Proposed / P2-S3**。

### 3.1 Domain Models

P2-S3 冻结以下 v1 Domain Models：

- `MedicalResearchBrief`
- `EvidenceNeed`
- `MedicalResearchTask`
- `SourceRecord`
- `EvidenceRecord`
- `ResearchFinding`
- `ResearchTaskResult`

#### MedicalResearchBrief

表示对用户医学问题完成 Clarify 之后形成的内部 research specification。

概念职责：

- `normalized_question`
- `question_type`
- `clinical_elements`
- `constraints`
- `research_intent`
- `evidence_needs[]`

`EvidenceNeed` 是 `MedicalResearchBrief` 的 nested domain object，而不是独立 Graph Stage。

本 Step 不要求一次冻结完整医学 taxonomy；无法由当前 EvidenceFlow domain samples 支撑的 enum 不应
凭经验过度设计。

#### EvidenceNeed

表示：

> 为回答当前医学问题，需要寻找什么性质或方向的 Evidence。

它是 EvidenceFlow planning intermediate representation，不声称属于外部医学标准。

其主要作用是连接：

```text
Medical Question Understanding
  → Research Planning
  → Retrieval / Research Task
```

#### MedicalResearchTask

表示 Agentic Supervisor 在运行时产生的一次具体研究委派。

最小职责包括：

- `task_id`
- `research_question`
- evidence requirements
- source preferences / constraints
- `priority`

P2-S3 必须保留 Supervisor 动态生成 0/1/N tasks 的能力，不迁移为一次性 Planner。

实现级 identity ownership：LLM-facing `ConductResearch` 只生成 `research_question`、nested
`evidence_needs`、`source_preferences` 和 `priority`。Host/Dispatcher 负责构造完整 Task；正常路径使用
`task:{encoded_tool_call_id}`，其中 encoding 必须 deterministic 且 lossless/injective；不同的原始
`tool_call_id` 不得生成相同 `task_id`。缺失 call ID 时使用
`task:iteration:{supervisor_iteration}:call:{ordinal}`。这是 run-local stable identity，不承诺跨 run
global identity，也不引入 `attempt_id`。

#### SourceRecord

表示一个可被稳定识别和追溯的外部来源。

v1 核心语义：

- `source_id`
- `artifact_ref`
- `metadata`

`metadata` 至少需要能够容纳来源定位和 retrieval provenance。

P2-S3 冻结以下 runtime compactness guardrail：

- `metadata` 的 canonical compact JSON serialization 不得超过 8000 characters；
- deterministic representation 使用
  `json.dumps(metadata, ensure_ascii=False, sort_keys=True, separators=(",", ":"))`；
- metadata keys 经过 case/separator-insensitive normalization 后，拒绝 `content`、`page_content` 与
  既有 raw/full-payload aliases；
- key rejection 是 defense-in-depth，不替代 serialized total bound。

8000-character limit 只控制 Graph State payload，不表示 source/evidence 的医学质量。

P2-S3 只冻结 `artifact_ref` abstraction，不实现 Artifact Store。

#### EvidenceRecord

表示从某个 Source 中选出的、能够作为事实依据参与后续 reasoning / grounding 的稳定 Evidence unit。

v1 核心语义：

- `evidence_id`
- `source_id`
- `locator`
- `excerpt`
- `hash`，语义为 content hash

为保持与 `EVIDENCEFLOW_CONTRACTS_V1.md` 一致，v1 canonical field name 是 `hash`，不额外增加
`content_hash` 字段。

Invariant：

```text
EvidenceRecord
  → 必须能够回溯到 SourceRecord
  → 必须能够定位到 source artifact 中的具体内容
```

`excerpt` 属于 Evidence semantic content，但完整 raw source artifact 不进入 Graph State。
P2-S3 冻结 `excerpt <= 8000 characters` 作为 structured State runtime compactness guardrail；该限制不
表示 evidence quality、support strength 或 medical sufficiency。

#### ResearchFinding

表示 Researcher 针对一个 `MedicalResearchTask`，基于一组 Evidence 得出的 task-local research
conclusion。

v1 核心语义：

- `finding_id`
- `task_id`
- `text`
- `evidence_ids[]`
- `limitations[]`
- `conflicts[]`

Finding 是 model-generated research interpretation，不属于 external Evidence。

#### ResearchTaskResult

表示 Researcher → Supervisor 的稳定业务输出 Contract。

概念结构：

- `contract_version`
- `task_id`
- `status`
- `findings[]`
- `evidence_ids[]`
- `source_ids[]`
- `limitations[]`
- `conflicts[]`
- `summary`
- optional `error`

冻结的 status convention：

- `contract_version` 必须序列化为 `evidenceflow.contracts.v1`，并以模块级 canonical constant 为代码
  来源；不新增 Result envelope，不向每个 Domain Model 复制该字段；
- Python enum members 为 `SUCCESS`、`PARTIAL`、`FAILED`；
- serialized values 为 `success`、`partial`、`failed`；
- `SUCCESS`：Researcher 正常终止并成功产生 compression / result output；显式 `ResearchComplete` 在与
  budget boundary 同一步发生时优先；
- `PARTIAL`：因 tool-call budget 或已识别的 tool failure 被迫终止，但仍成功产生可使用的 partial
  output；
- `FAILED`：admission、child execution 或 compression failure 阻止正常完成 result boundary；已经
  到达 finalization/failure boundary 且通过 validation 的 Source/Evidence/Finding references 不得因此
  丢失；hard child exception 返回 State 前的 partial recovery 不在 P2-S3 guarantee 内。

这些 status 只表达 P2-S3 execution / termination semantics，不是独立验证过的 Evidence sufficiency、
Evidence quality、coverage、grounding 或医学正确性判断。

v1 不包含：

- `open_questions`
- `suggested_tasks`
- `source_count`
- `evidence_count`
- `coverage_score`
- `quality_score`

原因：

- 当前 Task 内仍然 unresolved 的 blocking question 应驱动 Researcher 继续 loop；
- 全局 research gap 属于 Supervisor 的规划职责；
- count / coverage 等可以作为 derived observation；
- quality score 属于 Runtime Verification 或 Offline Evaluation，而不是 `ResearchTaskResult` 的核心事实字段。

P2-S3 使用 shadow Result 接通真实 runtime：`summary` 来自同一次 execution 的
`compressed_research`，而 `findings/evidence_ids/source_ids` 暂时允许为空。空集合只表示 structured
Evidence population 尚未实现，不能解释为 legacy Researcher 未使用来源或证据。并发 admission failure
与 child execution failure 也必须为已 materialize Task 产生 `FAILED` Result。

P2-S3 只保证 candidate Result references 在 Researcher finalization 时能对 Researcher-local
`source_records` / `evidence_records` 完成 provenance validation。当前 `ResearcherOutputState` 不携带
Source/Evidence registries，P2-S3 不新增 Parent registry 或 EvidenceStore，因此不保证 populated IDs 在
Parent boundary 已经可解析。P2-S4 真实 population 开始前必须先实现 record carry、inline envelope 或
run-scoped registry，使所有 Parent-visible IDs 可解析。

normal、partial 和 failed candidate Result 在 publish/finalization boundary emit 前必须调用现有
provenance validator；invalid Source/Evidence/Finding references 不得跨过 structured boundary。

### 3.2 Agentic Observation Boundaries

P2-S3 冻结 observation 的语义边界，但不新增独立 `ObservationRecord` Domain Model，也不新增
Observation Node。

Observation 是 Agentic decision input，不等于 Verification 或 Offline Evaluation。

#### Researcher Observation

Researcher 依据 local task context 决定继续或终止 research loop。该决定可以包含模型自身的 local
sufficiency assessment，但 P2-S3 不对该判断增加独立 Evidence quality verification。

主要观察：

- `MedicalResearchTask`
- search history
- tool observations
- current Source / Evidence
- current Findings
- conflicts
- limitations
- runtime iteration / budget state

Researcher 判断：

> 当前 ResearchTask 是否已经研究充分？

若不充分且仍可继续：

```text
continue research loop
```

若 Researcher 正常终止且成功产生 result output：

```text
SUCCESS
```

若由于 budget / tool failure 被迫终止，或 result boundary 无法正常完成：

```text
PARTIAL / FAILED
```

#### Supervisor Observation

Supervisor 负责 global Research Brief sufficiency。

主要观察：

- `MedicalResearchBrief`
- `ResearchTaskResult[]`
- aggregated Findings
- Evidence / Source derived coverage
- conflicts
- limitations
- runtime iteration / budget state

Supervisor 判断：

> 整个 MedicalResearchBrief 是否已经研究充分？

并动态决定：

```text
ConductResearch(...)
```

或：

```text
ResearchComplete
```

Researcher 不负责决定全局下一步 research task。

### 3.3 Graph State Contracts

P2-S3 需要明确：

```text
Domain Model
≠
Graph State Schema
```

Domain Model 定义业务对象。

Graph State Schema 决定哪些 Domain Objects 和 runtime values 需要跨 Node / Subgraph execution 保留为
LangGraph state channels。

#### Parent Graph State

首版至少需要评估并冻结以下语义：

- `messages`
- `medical_research_brief`
- `research_results`
- `final_report`

其中 `research_results` 用于承载 Supervisor 可观察的 ResearchTask-level outputs。

实际字段命名和 legacy state integration 必须先根据当前源码确认，禁止仅依据本计划强制重命名现有字段。

#### Supervisor State

Supervisor State 继续服务：

- global planning
- delegation
- research iteration
- result aggregation

应能够访问：

- `medical_research_brief`
- ResearchTaskResult-level observations
- existing legacy notes where compatibility requires
- runtime iteration state

P2-S3 不要求立即删除：

- `notes`
- `raw_notes`

#### Researcher-local State

Researcher State 负责单个 ResearchTask 的局部执行状态。

目标语义包括：

- `task`
- `researcher_messages`
- `tool_call_iterations`
- source records / refs
- evidence records / refs
- `findings`
- `compressed_research`
- `raw_notes`

其中 `compressed_research` 和 `raw_notes` 属于 legacy compatibility path。

P2-S3 可以定义 Source / Evidence / Finding channels，但完整 Evidence-native population 逻辑属于 P2-S4。

### 3.4 State / Artifact Boundary

Graph State 不负责持久化 raw artifacts。

以下内容不得作为新的 EvidenceFlow structured Graph State payload：

- full raw HTML
- full PDF text
- binary documents
- large search-provider raw payloads
- large immutable source snapshots

这些内容未来由 Artifact Store 管理。

Graph State 主要保留：

- stable IDs
- domain objects
- compact excerpts where necessary
- summaries
- runtime status
- artifact references

P2-S3 对 new structured channels 冻结：

- `EvidenceRecord.excerpt <= 8000 characters`；
- `SourceRecord.metadata` canonical compact JSON serialized total `<= 8000 characters`；
- normalized content-bearing metadata-key rejection 继续作为 defense-in-depth。

这些是 runtime compactness guardrails，不是 medical evidence semantics。

P2-S3 只冻结该 boundary，不实现 Artifact Store。

临时迁移例外：当前 ODR summarization failure path 可能把 raw webpage content 通过 legacy
`ToolMessage/raw_notes` 写入 State。P2-S3 不修改该 Tavily fallback，但该例外不得扩展到
`medical_research_brief`、`research_results`、`source_records`、`evidence_records`、`findings` 或
`research_task_result`。P2-S4 引入 ArtifactStore boundary 时必须移除该例外。

### 3.5 Parent / Researcher Boundary

目标业务边界：

```text
MedicalResearchTask
        ↓
Researcher Subgraph
        ↓
ResearchTaskResult
```

Parent / Supervisor 不依赖 Researcher 内部：

- individual AIMessage
- individual ToolMessage
- search implementation detail
- tool-loop scratch state

如果 Parent Graph State 与 Researcher State schema 不同，应使用当前 ODR 已有 delegation / adapter
boundary 显式完成数据转换，而不是强制共享一个大型 State Schema。

P2-S3 当前只保证 Researcher-local provenance consistency。因为 shadow Result 尚未真实 population，且
本阶段不增加 Parent registry，所以 populated Source/Evidence IDs 的 cross-boundary resolvability 不是
P2-S3 implementation guarantee；它是 P2-S4 real structured population 的 mandatory prerequisite。

P2-S3 partial-artifact preservation 只覆盖 finalization/failure boundary 已经能够取得且通过 validation 的
records。hard child exception 若在 `researcher_subgraph.ainvoke()` 返回 State 前逃逸，Parent 只能生成
task-correlated FAILED Result，不能恢复不可见 child State。State-aware recovery 延后到 P2-S4/P2-S6。

### 3.6 State Update Semantics

P2-S3 必须对主要 channels 冻结业务级 update semantics。

| Channel | Update semantics |
|---|---|
| `medical_research_brief` | replace |
| `research_results` | append by distinct task ID；identical replay dedup；conflicting replay fails |
| source records / refs | append / deduplicate |
| evidence records / refs | append / deduplicate |
| `findings` | append |
| `tool_call_iterations` | replace / increment semantics |
| legacy `raw_notes` | preserve existing reducer semantics unless explicitly migrated |

本 Step 冻结业务语义，但不要求所有 deduplication 都通过 LangGraph Reducer 实现。

Reducer implementation 应以当前代码和实际 concurrency requirements 为依据。

P2-S3 不执行同一 Result 的 field-wise merge。未来如果需要 per-task retry，必须先区分 logical
`task_id` 与 execution `attempt_id`，不得复用 conflicting replay 覆盖 immutable Result。

### 3.7 Contract Invariants

P2-S3 至少冻结以下 invariants：

**I1**

Every `MedicalResearchTask` has a stable `task_id`.

**I2**

Every `SourceRecord` has a stable `source_id`.

**I3**

Every `EvidenceRecord` references a valid `SourceRecord`.

P2-S3 由 Researcher publish gate 对 local records 验证；P2-S4 real population 前再保证 Parent-visible
cross-boundary resolution。

**I4**

Every `EvidenceRecord` preserves auditable source provenance through
`source_id + locator + content hash / artifact reference`.

P2-S3 验证 Researcher-local graph consistency；artifact content audit 与 Parent-visible record resolution
属于 P2-S4 prerequisite。

**I5**

AIMessage / model-generated content cannot become external Evidence.

**I6**

Every normal `ResearchFinding` references valid Evidence IDs. Evidence-insufficient results must be explicitly
represented rather than silently fabricating Evidence.

P2-S3 publish gate 必须在 local Evidence collection 中解析 Finding references。

**I7**

Parent Graph must not depend on Researcher internal message history or tool-loop implementation details.

**I8**

Raw source artifacts must not be persisted in new structured Graph State channels. Existing legacy
`ToolMessage/raw_notes` raw-content fallback is a temporary P2-S3 exception and must not be extended.

New structured records 同时受 8000-character excerpt/metadata guardrails 约束。

**I9**

Legacy `raw_notes` / `compressed_research` and the new structured contracts may coexist during migration.

**I10**

Derived values such as `evidence_count` / `source_count` should not be persisted when they can be deterministically
calculated from IDs.

## 4. Non-goals

P2-S3 明确不实现：

- Evidence Store
- Artifact Store
- RAG / vector retrieval
- PubMed-specific integration
- ClaimRecord implementation
- Claim–Evidence Grounding
- Citation rendering / resolver
- Grounding Verifier
- Final Report Quality Verifier
- dedicated Observation Node
- dedicated Researcher Quality Verifier
- Plan + Send migration
- Durable Queue
- new distributed Worker architecture
- Supervisor algorithm rewrite
- Search Provider migration
- complete medical evidence hierarchy automation
- complete trajectory evaluation
- online evaluation
- Parent Source/Evidence registry 或 EvidenceStore
- checkpoint-based hard child-state recovery
- retry / `attempt_id` lifecycle
- new persistence used only to recover partial child State

P2-S3 不因“未来可能需要”而提前引入 infrastructure。

## 7. Acceptance Criteria

### 7.1 Contract

- MedicalResearchBrief、EvidenceNeed、MedicalResearchTask、SourceRecord、EvidenceRecord、
  ResearchFinding、ResearchTaskResult 均具有明确职责。
- Domain Model 与 LangGraph State Schema 明确分离。
- EvidenceNeed 不成为额外 Graph Stage。
- ResearchTaskResult 不承担 Supervisor planning responsibility。

### 7.2 State

- Parent / Supervisor / Researcher state boundary 明确。
- 新增 state channels 的 update semantics 明确。
- 新 structured channels 不引入 raw source artifact state bloat；legacy `raw_notes` 例外被隔离并记录为
  P2-S4 removal target。
- `EvidenceRecord.excerpt` 与 serialized `SourceRecord.metadata` 均执行 8000-character runtime
  compactness guardrail；normalized content-bearing-key rejection 继续生效。
- Parent Graph 不依赖 Researcher internal message / tool details。

### 7.3 Provenance

- Evidence 必须引用有效 Source。
- Evidence 必须具有 locator 和稳定 provenance。
- model-generated Finding 不能被标记为 external Evidence。
- invalid Source / Evidence references 能够被 deterministic validation 捕获。
- normal、partial 与 failed candidate Result 在 Researcher publish/finalization boundary 发出前必须通过
  provenance validation；invalid Finding/Evidence/Source references 不得跨过 structured boundary。
- P2-S3 只保证 Researcher-local provenance consistency；P2-S4 real population 前必须使每个
  Parent-visible Source/Evidence ID 能跨 boundary resolve。

### 7.4 Runtime

- 保留现有 Agentic Supervisor–Researcher Tool Loop。
- Supervisor 仍然能够动态产生 0/1/N ResearchTasks。
- 不引入 Send。
- 不引入独立 Planner。
- 不引入 Evidence Store / Artifact Store。
- 不改变 Search Provider architecture。

### 7.5 Compatibility

- Legacy `compressed_research` / `raw_notes` path 在 P2-S3 后仍可工作，或存在明确且经过测试的兼容
  adapter。
- Existing baseline behavior 不发生无意 regression。

### 7.6 Testing

至少覆盖：

- schema validation
- invalid contract rejection
- ID / provenance invariants
- state update semantics
- ResearchTaskResult status handling
- ResearchTaskResult serialized contract-version discoverability
- legacy compatibility
- structured brief output
- structured research task delegation

外部 LLM / search provider 调用不作为 deterministic unit test。

### 7.7 Runtime Smoke

至少完成一条真实医学问题：

```text
Question
  → Clarify
  → MedicalResearchBrief
  → Supervisor
  → MedicalResearchTask Tool Call
```

并验证新的 structured contract 确实穿过实际 Agent runtime。

P2-S3 不要求该 smoke 完成 Evidence-native Researcher output；该部分属于 P2-S4。

## 9. Risks

### R1 — Over-modeling

过早为未来 Claim / RAG / Store / medical taxonomy 建立大量对象，会增加迁移成本。

Mitigation：

- 只实现当前 P2-S3 必需 Contract。
- Future concepts 只冻结 boundary，不冻结 implementation。

### R2 — State Bloat

将完整 Source、HTML、PDF 或大量 raw tool outputs 放入 Graph State 会增加 checkpoint / serialization
成本。

Mitigation：

- new structured channels 遵守 raw artifact 外置原则；
- State 只保存必要 Domain Object、compact excerpt、ID 和 reference。
- legacy `ToolMessage/raw_notes` fallback 作为限于 P2-S3 的已知例外记录，并在 P2-S4 移除。

### R3 — Responsibility Leakage

Researcher 如果开始决定全局下一步任务，会与 Supervisor planning responsibility 重叠。

Mitigation：

- Researcher 只输出当前 Task 的结果、limitations、conflicts 和 status；
- global research gap 由 Supervisor 推导。

### R4 — Legacy Regression

一次性替换 `compressed_research` / `raw_notes` 可能破坏现有 ODR final report path。

Mitigation：

- P2-S3 / P2-S4 允许 structured + legacy dual-path / adapter migration。

### R5 — Prompt / Contract Drift

修改 structured schema 后，Prompt 仍然按照旧 free-form contract 工作，可能导致 schema-valid 但语义
错误的输出。

Mitigation：

- Domain schema、Prompt 和 contract test 一起审查。

### R6 — Premature Quality Nodes

为了“提高质量”过早增加 Researcher Verifier / Supervisor Verifier，会与现有 Agentic self-assessment
职责重叠并增加 LLM calls。

Mitigation：

- P2-S3 只冻结 observation / sufficiency boundary。
- 新的 verifier 必须由后续 Eval evidence 驱动。

### R7 — Medical Taxonomy Overconfidence

PICO、question type、study type、evidence hierarchy 等领域字段如果未经样本和依据验证就冻结为大量
enum，可能导致 contract 过早僵化。

Mitigation：

- v1 优先冻结语义和最小字段；
- 精确 taxonomy 由 P2-S3 domain samples / later evidence 支撑后收紧。

### R8 — Hard Child Exception Partial-State Loss

`researcher_subgraph.ainvoke()` hard exception 在返回 State 前逃逸时，Parent catch 无法取得 child-local
Source/Evidence/Finding，即使它们可能已在前序 node materialize。

Mitigation：

- P2-S3 保证 finalization/failure boundary 可见的 valid records 被保留；
- Parent 仍生成 task-correlated FAILED Result 并保留 error visibility；
- 不在 P2-S3 引入 checkpoint、retry/attempt lifecycle、新 persistence 或 topology change；
- P2-S4 evidence-native finalization 与 P2-S6 reliability design 继续评估 state-aware recovery。
