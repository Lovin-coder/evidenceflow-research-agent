## 2. P2-S4 Goal

P2-S4 将当前 ODR Researcher：

```text
Search
→ formatted text
→ Researcher reasoning
→ compressed_research
```

改造成：

```text
Search
→ SourceRecord
→ source-derived EvidenceRecord
→ Researcher reasoning
→ provenance-preserving ResearchFinding
→ ResearchTaskResult
```

迁移期间继续保留：

- legacy `ToolMessage`；
- legacy `compressed_research`。

它们是 model-facing / compatibility projection，structured artifacts 是新的 authoritative data path。

P2-S4 的目标不是单纯增加 LLM calls，而是建立清晰的 trust boundary：

```text
Semantic decision
    → LLM

Identity / locator / excerpt / validation
    → Host runtime
```

## 5. P2-S4 Critical Path

Search ingestion 主链冻结为：

```text
Researcher Tool Call
        ↓
researcher_tools
        ↓
structured Tavily execution
        ↓
provider SearchResult
        ↓
usable source-content gate
        │
        ├── No
        │     ↓
        │  warning / trace only
        │  no SourceRecord
        │  no EvidenceRecord
        │
        └── Yes
              ↓
      normalize_source_text()
              ↓
        normalized source text
              ↓
          ArtifactStore
              ↓
          SourceRecord
              ↓
    deterministic chunking
              ↓
        CandidateChunk[]
              ↓
      summarization model
              ↓
  summary + selected_chunk_ids
              ↓
        Host validation
              ↓
       EvidenceRecord[]
              ↓
     SearchExecutionResult
          ├──────────────┐
          ↓              ↓
      Data Plane      ToolMessage
          ↓              ↓

```

这里冻结三个不同可信级别：

```text
SearchResult ≠ SourceRecord
CandidateChunk ≠ EvidenceRecord
ResearchFinding ≠ EvidenceRecord
```

`SearchResult` 只是 provider discovery observation。只有成功取得 usable、inspectable raw content，并通过
Host ingestion gate 的 result，才 materialize 为 authoritative `SourceRecord`。只有被 LLM 选中并由 Host
从 Source exact slice materialize 的 Candidate，才成为 `EvidenceRecord`。

Researcher loop 结束后：

```text

+

        ↓
compress_research
        ↓
ResearchFinding[]
+
summary
+
limitations
        ↓
ResearchTaskResult
        ↓
bounded projection
        ↓
Supervisor
```

Cross-agent publication boundary 冻结为：

```text
Researcher local Source/Evidence ledgers
        ↓
compress_research
        ↓
Finding validation
        ↓
assemble self-contained ResearchTaskResult
        ↓
Publication Gate
        ↓
ResearcherOutputState
        ↓

```

## 6. Deterministic Chunking Design

Chunking 只负责把大体积 `raw_content` 确定性转换成 bounded、contiguous、可定位的 Evidence candidates。

```text
chunking
≠ retrieval
≠ relevance ranking
≠ Evidence quality judgment
```

### 6.1 Source Text Normalization

Evidence locator 必须针对稳定文本空间：

```text
Tavily raw_content
        ↓
normalize_source_text()
        ↓
normalized_source_text
        ↓
ArtifactStore
        ↓
chunking
```

`artifact_uri` 对应的必须是 chunker 实际使用的 exact normalized text，保证：

```text
locator
→ artifact
→ exact slice
```

可以由 deterministic code 验证。

初始 normalization 仅做轻量、可解释处理：

- `CRLF / CR → LF`；
- remove NUL / invalid control characters；
- trim line-ending whitespace；
- collapse excessive blank lines；
- trim document head/tail whitespace。

不进行 LLM cleaning、semantic rewrite、sentence paraphrase 或 HTML meaning reconstruction。Tavily 负责主要网页
抽取，本项目不重新实现 crawler/parser。

### 6.2 Locator Protocol

S4 MVP 使用 character offset：

- `start` inclusive；
- `end` exclusive；
- 示例：`char:1280-2471`。

必须满足：

```python
artifact_text[start:end] == evidence_record.excerpt
```

### 6.3 CandidateChunk Internal Representation

`CandidateChunk` 不是 Domain Model，只是 internal immutable value object：

```python
@dataclass(frozen=True)
class CandidateChunk:
    chunk_id: str
    start: int
    end: int
    text: str
```

`chunk_id` 只在当前 webpage selection call 内有效，可使用 `C001`、`C002`、`C003`。稳定 Evidence identity
在 Host materialization 时生成。

### 6.4 Chunk Boundary Strategy

S4 采用 `paragraph-first deterministic packing + deterministic fallback splitting`，不使用纯 fixed-window
character slicing。

Stage A — logical blocks：优先按 blank-line paragraph boundaries 和 Markdown-like headings 形成连续 blocks，
并保留原始 offset。

Stage B — oversized block splitting：单个 paragraph 超过 `MAX_CANDIDATE_CHARS` 时，按以下顺序切分：

```text
sentence boundary
→ whitespace boundary
→ hard character boundary
```

全部由 deterministic code 完成，不使用 LLM sentence segmentation。

Stage C — adjacent block packing：按原文顺序 greedy packing。Candidate 必须 contiguous，禁止把不相邻的
paragraph 拼成一个 Candidate。

### 6.5 Initial Chunk Budget

初始 tuning range：

- `TARGET_CANDIDATE_CHARS ≈ 1000–1200`；
- `MAX_CANDIDATE_CHARS ≈ 1600–1800`；
- `MIN_TAIL_CHARS ≈ 250–300`；
- `overlap = 0`。

实现采用的确切 constant 必须满足：

```text
MAX_CANDIDATE_CHARS <= MAX_EVIDENCE_EXCERPT_CHARS
```

这些值属于 PLAN-level tuning，可通过固定医学网页 fixtures 小范围调整，不需要修改 SPEC。

S4 MVP 不使用 overlap，以避免 repeated Candidate → repeated Evidence → dedup complexity。真实 evaluation 若证明
存在 cross-boundary information loss，再单独评估 overlap。

### 6.6 Tail Handling 与 Determinism

若最后 Candidate 小于 `MIN_TAIL_CHARS`，且与前一个 Candidate 合并后不超过
`MAX_CANDIDATE_CHARS`，则确定性 merge 回前一个 Candidate，否则保留。

相同 `normalized_source_text + chunking version/config` 必须产生完全相同的 Candidate count、`start`、
`end`、`text` 与 ordering。

## 7. Evidence Selection

Candidate 生成后才发生 semantic selection：

```text
CandidateChunk[]
        ↓
summarization model
        ↓
selected_chunk_ids[]
```

LLM 负责判断哪些 passage 对当前 `MedicalResearchTask` 有意义，但不拥有 identity、locator 或 Evidence content。

### 7.1 Reuse Existing Summarization Call

S4 不单独增加 Evidence extraction model call，而是将现有 webpage summarization：

```text
raw_content
→ summarization model
→ summary
```

升级为：

```text
CandidateChunk[]
+
Research Task / Search Query
        ↓
same summarization model call
        ↓
summary
+
selected_chunk_ids
```

一次 semantic call 同时服务 legacy summary 与 structured Evidence selection。

### 7.2 Selection Context

模型至少看到：

- Research Task / `research_topic`；
- Search query；
- Source title；
- Source URL；
- Candidate chunks。

internal structured Tavily executor 可额外接收 `research_topic`，但不得改变 Agent-visible web-search Tool schema。

### 7.3 WebpageSelection Internal Schema

新增 internal schema：

```python
class WebpageSelection(BaseModel):
    summary: str
    selected_chunk_ids: list[str]
```

要求：

- `extra="forbid"`；
- `selected_chunk_ids` unique；
- selected count bounded；
- unknown IDs 由 Host validator 拒绝。

它不是 Domain Model。

### 7.4 Selection Policy

Prompt 只要求模型判断 relevance and information value，而非最终 truth：

- 只选择与 `research_topic` / query 直接有关的 chunks；
- 优先具体事实、结果、数字、recommendation、limitation；
- 避免同一 Source 中高度重复表达；
- 保留相关 conflict 或 limitation；
- 跳过 navigation、reference list、boilerplate；
- 使用最小必要 Evidence set；
- 每个 Source 选择数量 bounded。

第一版建议 `MAX_SELECTED_CHUNKS_PER_SOURCE = 4`，后续通过 evaluation 调整。

Host 不进行 semantic merge；两个被选 Candidate 仍是两个 contiguous Evidence artifacts。

## 8. Evidence Materialization 与 Provenance

LLM 返回 Candidate IDs 后，Host 执行：

```text
validate IDs
→ resolve CandidateChunk
→ resolve Source/artifact
→ exact excerpt
→ locator/hash
→ materialize EvidenceRecord
```

authoritative 字段全部来自 Host：

- `source_id`；
- `evidence_id`；
- `locator`；
- `excerpt`；
- `content_hash`；
- artifact URI/reference。

若现有源码没有 deterministic Evidence ID builder，采用 versioned hash，并至少将 `source_id + locator +
excerpt_hash` 作为 identity material。确切 encoding、prefix 和 hash algorithm 属于 implementation detail。

Evidence materialize 后立即验证：

```text
Evidence.source_id exists
locator valid
artifact exists
artifact[start:end] == excerpt
hash(excerpt) == content_hash
```

该过程完全由 code 完成，不调用 LLM。

## 9. ArtifactStore MVP

P2-S4 只实现 minimal file-backed Store：

```python
class ArtifactStore(Protocol):
    def put_text(...) -> str: ...
    def get_text(...) -> str: ...
```

测试使用 `tmp_path`，runtime 使用 configurable local directory。禁止引入 PostgreSQL、S3、MinIO、Redis、
SQLAlchemy、新依赖或跨 Run Search Cache lifecycle。

ArtifactStore 保存的是 chunking 使用的 exact normalized source text；Graph State 只持有 opaque artifact ref、
compact Source metadata、bounded Evidence excerpt 和 structured Finding。

### 9.1 ArtifactStore Lifetime

ArtifactStore scope 是 **run-scoped**，不是 Researcher-call-scoped：

```text
one EvidenceFlow Run
→ one resolvable ArtifactStore namespace
→ all Researcher invocations share resolution lifetime
→ published artifact_ref remains readable after child return
```

实现 MUST 保证 originating Researcher 返回后，publication gate、Supervisor boundary 后的 deterministic
provenance validation、debug/audit 与该 Run 的 downstream system stages 仍可 `get_text(artifact_ref)`。

Store object、root path 与 raw normalized text 不进入 Graph State；State 只保存 opaque `artifact_ref`。具体
run namespace/ref encoding 与 injection/factory mechanics 是 implementation detail，但不得退化为每次
Researcher call 结束即失效的 temporary directory。

P2-S4 不定义 Run 结束后的 retention、GC、durable persistence、transaction、object-storage migration 或
cross-run cache lifecycle。

## 10. Structured Tavily Execution

为避免把 Data Plane stringify 到 `ToolMessage` 后再 parse，增加 internal transport object：

```python
@dataclass
class SearchExecutionResult:
    model_content: str
    sources: list[SourceRecord]
    evidences: list[EvidenceRecord]
    warnings: list[str]
```

它不是 Domain Model。

### 10.1 Minimal-invasive Refactor

建议拆成两层。

Internal structured executor：

```python
async def execute_tavily_search_structured(
    ...,
    research_topic: str | None,
    config: RunnableConfig,
) -> SearchExecutionResult:
    ...
```

负责 Tavily request、usable content gate、Source construction、ArtifactStore、chunking、selection、Evidence
materialization 和 model-facing rendering。

Agent-visible Tool wrapper 继续保留现有 `tavily_search` Tool schema：

```python
result = await execute_tavily_search_structured(...)
return result.model_content
```

不得改变 Tool name、arguments、Researcher prompt 或 Tool binding。

### 10.2 Usable Source-content Gate

每条 Tavily result 必须先通过 content gate：

```text
missing / empty / unusable raw_content
→ no authoritative SourceRecord
→ no EvidenceRecord
→ ingestion warning / trace only
```

只有 usable `raw_content` 经 normalization 后，才允许持久化 Artifact 并 materialize `SourceRecord`。
Provider snippet、formatted content、Tool Error 或 arbitrary model summary 不得作为 fallback Evidence，也不得为了保留
URL 而创建无法审计的 authoritative Source。

## 11. researcher_tools Dual-channel Integration

`researcher_tools` 继续作为 Tool execution dispatcher / handler。

Tavily branch：

```text
SearchExecutionResult.model_content
→ ToolMessage

SearchExecutionResult.sources
→ ResearcherState.source_records

SearchExecutionResult.evidences
→ ResearcherState.evidence_records
```

其他 Tool 继续走 `execute_tool_safely()`；不得重写 generic Tool runtime。

保留现有 `asyncio.gather(...)` concurrency：多个 Tool calls parallel execution，结果按原始 Tool Call 顺序
aggregate messages 与 structured records。

### 11.1 Model-facing Search Rendering

`ToolMessage.content` 使用 bounded rendering，而非 JSON dump 或 raw webpage：

```text
Source: [S...]
Title: ...
URL: ...

Summary (derived, non-evidence):
...

Selected Evidence:

[E...]
exact excerpt
```

必须明确区分 derived summary 与 source-derived Evidence。Researcher 读取 bounded Source metadata、summary 和
selected Evidence excerpts，再判断 research gap 或是否继续 Search。

## 12. compress_research Refactor

Search path 打通后，再将 `compress_research` 改造成 provenance-preserving compression。

authoritative input 是 `EvidenceRecord[]`，向模型显式 render Evidence ID 与 exact excerpt。Structured output
生成：

- `ResearchFinding[]`；
- `summary`；
- `limitations`。

每个 `ResearchFinding.evidence_ids` 必须 resolve 到 authoritative Evidence collection。Unknown ID 是 validation
failure。

Compression 不得：

- create Source；
- create Evidence；
- modify Evidence excerpt；
- rebind Evidence to another Source。

同一次 compression dual-write structured Findings 与 legacy `compressed_research`。

### 12.1 Result Assembly

`compress_research` 完成 semantic compression 后，Host 执行独立的 Result assembly responsibility：

```text
ResearcherState.source_records
+ ResearcherState.evidence_records
+ validated ResearchFinding[]
+ status / summary / limitations / conflicts / error
        ↓
assemble ResearchTaskResult
        ↓
source_records / evidence_records inline
+ deterministic source_ids / evidence_ids projections
```

Result assembly 不重新 materialize Source/Evidence，不从 legacy string parse records，也不加载 raw artifact
进入 Result。Selector/compression failure 时，只组装在 selected finalization/failure boundary 已经 valid 的
compact records。

S3 shadow compatibility 使用 empty inline lists；P2-S4 populated Result 不得使用 empty defaults 发布非空 IDs。

### 12.2 Publication Gate

任何 `SUCCESS`、`PARTIAL` 或 `FAILED` populated Result 在进入 `ResearcherOutputState` 前 MUST 完成：

1. `source_records` / `evidence_records` / Findings identity uniqueness；
2. `source_ids` exactly and deterministically project `source_records` identities；
3. `evidence_ids` exactly and deterministically project `evidence_records` identities；
4. every `EvidenceRecord.source_id` resolves within the same Result；
5. every identity in `ResearchFinding.evidence_ids` resolves within the same Result；
6. every published Source has a non-empty run-scoped `artifact_ref`；
7. every `artifact_ref` resolves through the active Run ArtifactStore；
8. locator parses as valid `[start, end)` coordinates；
9. `artifact[start:end] == EvidenceRecord.excerpt`；
10. recomputed excerpt hash equals `EvidenceRecord.hash`；
11. per-record and total Result provenance payload bounds pass；
12. no raw Source artifact or provider payload is embedded in the Result。

任何 gate failure MUST prevent invalid Result publication。Gate 自己不得把 LLM/process/error content 转换成
Evidence，也不得删除其他可以组成 valid partial Result 的 records。

## 13. ResearchTaskResult 与 Supervisor Projection

`ResearchTaskResult` logical boundary 必须保留 downstream groundedness、citation、debugging、evaluation 所需的
完整、可解析 structured records，包括 Source、Evidence、Finding、status、summary、limitations。

S4-D15 已冻结 representation：`ResearchTaskResult` inline compact `source_records` / `evidence_records`，并保留
deterministic `source_ids` / `evidence_ids` projections。Parent 不增加 sibling Source/Evidence registries。

`ResearcherOutputState` 继续只跨边界投影 stable Result 与 legacy compatibility outputs；inline ledgers 作为 Result
的一部分跨边界，而完整 `ResearcherState`、messages、Candidates 与 raw artifacts 不跨边界。

Supervisor model-facing projection 主要 render：

- status；
- summary；
- Findings；
- limitations；
- conflicts。

完整 Source/Evidence 留在 Data Plane，不要求全部进入 Supervisor message context。

## 14. Failure Model

| Failure point | Source | Evidence | Finding | Required behavior |
|---|---|---|---|---|
| Tavily request failure | none | none | none | explicit Tool/retrieval error |
| result missing/unusable `raw_content` | none | none | none | warning/trace only；不得 materialize Source |
| one sibling result malformed | valid siblings preserved | valid siblings preserved | n/a | per-result isolation |
| selector failure after accepted Source | preserve | none for failed selection | n/a | preserve Artifact，record warning |
| unknown selected Candidate ID | preserve | invalid selection rejected | n/a | no fabricated Evidence |
| Evidence provenance failure | preserve | offending Evidence rejected | n/a | preserve other valid Evidence |
| compression failure | preserve | preserve | absent/failed | status 按 S3 frozen semantics 映射 |

任何 later-stage handled failure 都不得删除已经 valid 的 earlier artifacts。Hard child exception 超出 finalization/failure
boundary 可见状态时，仍受 S3 已记录 limitation 约束；P2-S4 不因此引入 checkpoint recovery、retry lifecycle 或 topology
change。

legacy path

topology
